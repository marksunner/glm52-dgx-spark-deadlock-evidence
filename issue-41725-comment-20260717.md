# Comment for vllm-project/vllm #41725 (sm_12x sampler event-sync hang) — for posting by Mark/Tars

We chased several multi-day hang classes on a 4× DGX Spark (GB10/sm_121)
GLM-5.2 TP=4 deployment and can contribute two data points to this issue's
class — all ranks frozen with equal per-rank collective counts, blocked in
`sample_tokens`:

1. We captured one hang matching this issue's class exactly (2026-07-15,
   "Type B" in our notes): all four ranks frozen with equal per-rank NCCL
   collective counts (NCCL RAS `ras_spread=0`), engine steps frozen equal,
   the stuck RPC being `sample_tokens`, no NCCL involvement — while a
   separate per-step cross-rank fingerprint detector we run showed zero
   pre-step divergence. NCCL RAS (enabled by default, port 28028) makes a
   cheap first discriminator between this class and collective-desync hangs:
   `echo -e "set format json\nverbose status" | nc localhost 28028` gives
   per-rank launched-op counts; equal-and-frozen points at this issue's
   class, spread>0 at a desync/wedge class. It is a first-pass sort, not a
   definitive classifier — confirm with stacks (py-spy/cuda-gdb) before
   attributing.

2. Most of what we initially attributed to sampler/event-sync hangs on this
   platform turned out to be a different bug entirely: the flashinfer
   `sparse_mla_sm120` attention kernels can livelock on GB10 (single block
   spinning forever at an mbarrier `SYNCS.PHASECHK.TRANS64.TRYWAIT`,
   cuda-gdb receipt; GPU reports 96 % util at ~18 W). Anyone debugging
   "96 % SM, low power, hosts stuck in cuLaunchKernel" hangs on sm_121
   sparse-MLA models should check that first — details in our RFC #48720
   thread update. Since routing the main model's attention to the Triton
   sparse-MLA path we have had zero wedges of any class: 560+ context-ceiling
   sessions (500 consecutive under our strictest config, ~25–27 tok/s at the
   120K boundary) plus a full cold staged climb to 200,000 tokens with a
   clean boundary completion at ~26 tok/s — the exact workload that
   previously wedged 8/8.

Practical debug notes for this platform: py-spy/cuda-gdb inside the
container require `docker exec -u root --privileged`; `nvidia-smi` power
draw is the fastest spin-vs-compute discriminator; and NCCL RAS is the
best always-on desync detector.
